# Phase 5: the shadow-read comparator

- Status: design only. Nothing here is scheduled, deployed or enabled.
- Scope: how a *future* comparator reads the **legacy** and **canonical** surfaces side by
  side, decides whether they answer the same question the same way, and produces evidence a
  read cutover can be gated on.
- Source of truth: `hear/verify/shadow_read.py`. Artifacts are generated by
  `tools/gen_shadow_read_contracts.py` into `docs/phase5-shadow-read/` and gated for drift
  in CI. Enforced by `tests/test_shadow_read_receipt_v1.py`.
- Decision record: `docs/decisions/0007-phase5-shadow-read-comparator.md`.
- Companions read rather than duplicated: `docs/phase4-dual-write-observability.md` (the
  write-side audit), `docs/phase2-postgres-migration-plan.md` §8 (the in-process sampler and
  the out-of-process comparator this generalises), `docs/api-boundaries.md` (cursor
  pagination, idempotency, error semantics), `docs/data-governance.md` (retention classes,
  deletion, holds).

**This document changes no reader.** No query is issued, no cluster or fleet or production
store is touched, no credential is minted, no row is written anywhere. `hear/verify/` is
imported by a generator and a test file and by nothing else, and a test asserts that stays
true.

---

## 1. Position

Phase 4 asks *did both writers store the same thing*. Phase 5 asks the question that
actually gates a cutover: **would a user have got the same answer?** Those are different
questions, and passing the first says very little about the second. Two stores can hold
byte-identical rows and still disagree about what a query returns, because a read is not a
row — it is a *filter*, a *window*, an *order*, a *page* and an *instant*, and each of those
five is somewhere the two paths can diverge with both stores perfectly healthy.

The position is the same as the write side, and it is not negotiable for the duration of
Phase 5:

| Invariant | Mechanism |
|---|---|
| **Legacy answers are authoritative** | `READ_AUTHORITY = "legacy"`, asserted by test and pinned as a `const` in the receipt schema. A build that flipped it would be a read cutover disguised as a comparator change. |
| **The comparator only runs where nothing has moved** | `assert_shadow_only()` accepts the `shadow` and `compare` lane modes of the Phase 3 read ladder and refuses `prefer` and `only`. Those two mean a reader already moved, and there is nothing left to shadow. |
| **The comparator is an auditor** | No write path into either subject, `disposition.queued` is always `false`, and repair is advisory. An auditor with write access to its subject is not an auditor. |
| **No cluster, fleet or production store access from this lane** | Everything in this PR runs against fixtures on a bare interpreter. The live comparator, when it is built, is read-only by the same `assert_read_only` rule the Phase 2 soak tool already enforces. |
| **No audio, no coordinates** | Clip bytes are never read at all; restricted fields are compared by the `blind` comparator, where equality is decided in memory and only the verdict is durable. |

## 2. What is compared

### 2.1 Evidence classes

Thirteen, closed. A read surface with no entry here is a `comparator_fault`, not a silently
skipped read.

| Evidence class | Legacy surface | Canonical surface | Coverage | Notes |
|---|---|---|---|---|
| `heartbeat` | receiver/bridge cache view | durable outbox reader | sampled | short-TTL on the legacy side; retention horizons differ by design |
| `health` | receiver health view | fleet-health reader | sampled | compared as a state surface, not a numeric history |
| `detection` | pool `dets` reader | canonical event reader | sampled | the highest-cardinality class |
| `scene` | pool scene reader | canonical scene reader | sampled | |
| `clip_manifest` | clip index | object-store clip manifest | sampled | **restricted**: manifest only, bytes never read |
| `tag` / `score` | pool tag/score lanes | canonical derived readers | sampled | `numeric` comparator with a declared tolerance and model-card identity |
| `localization` | solver output files | localization reader | sampled | solution coordinates are `blind` |
| `annotation` | annotations database | canonical label reader | sampled | human labels, `R3-evidence` |
| `export_manifest` | export artifacts | export reader | **exhaustive** | low cardinality, high consequence |
| `ledger_stat` | `pool.stats()` | canonical aggregate | **exhaustive** | the Phase 3 key design requires these to be identical in every mode |
| `model_card` | model registry files | model reader | **exhaustive** | an artifact is never mutated, so any difference is real |
| `audit_record` | audit ledger | canonical audit reader | **exhaustive** | `R4-audit`, append-only |

Sampling an aggregate is not cost control — it is deleting the only number anybody reads.
That is why the four exhaustive classes are exhaustive regardless of budget pressure.

### 2.2 The compared projection

As on the write side, the compared state is an **explicit projection**, never a whole stored
row. Hashing a whole row makes every additive field a mismatch, and that is the comparator
people switch off in week two.

| Comparator | Applied to | Tolerance |
|---|---|---|
| `hash` | retained raw objects, clip digests | SHA-256 equal |
| `exact` | identity strings, GPS-anchored instants | equal |
| `tier` | unanchored instants | clock tier equal, **value ignored** |
| `count` | counters, row counts, aggregates | equal |
| `numeric` | solver/model outputs | `abs diff ≤ declared tolerance` **and** model-card identity equal |
| `set` | whole result sets | identity-keyed set equality over the settled window |
| `order` | the declared sort key | identical key sequence over the intersection; inversions counted |
| `presence` | optional restricted fields | null-ness and precision class equal, value ignored |
| `blind` | coordinates, credentials, clip bodies | equality decided **in memory**; only the verdict is durable |

`result_hash()` is deliberately **order-independent** — it digests the sorted set of row
projections. Folding order into the content digest would make "one late row" and "one
re-sorted page" indistinguishable, and those have different repairs.

## 3. Query identity

Both sides must be asked the same question, and "the same" has to survive two clients that
spell a filter differently. `normalise_query()` produces a closed normal form — evidence
class, site, sorted device ids, bounds, sorted filters, sort key and direction, page size,
`as_of`, settle horizon, projection version — and `query_fingerprint()` is a SHA-256 over
its canonical JSON.

Three rules make the fingerprint load-bearing:

1. **An unknown key is folded in, not dropped.** A newer comparator's filter that vanished
   from the fingerprint would let the two sides be asked different things and still "agree".
2. **A pair whose two sides report different fingerprints is `filter_divergence`**, judged
   before any row comparison. An inclusive versus half-open upper bound is the usual cause,
   and every row-level verdict downstream of a different question is an artefact rather than
   a finding.
3. **A row identity is never re-derived.** `row_key()` folds evidence class, site, device and
   the `logical_id` each surface *already recorded* — a `record_uid`, an `event_id`, a clip
   id, an object logical id. A comparator that reimplements the identity it audits can make
   both sides agree on a bug, which is the exact trap ADR 0005 rejected on the write side.

## 4. Time: a read is a snapshot, not a row

Two stores do not commit at the same instant, and two reads do not happen at the same
instant either. Four bounds carry that.

| Bound | Value | Meaning |
|---|---|---|
| `SETTLE_S` | 900 s | Rows newer than `as_of − SETTLE_S` are **excluded from comparison**, not compared and forgiven. Comparing the leading edge of a write stream measures scheduling jitter and calls it data loss. |
| `BACKFILL_SETTLE_S` | 86 400 s | The same horizon for drain/import lanes, where a day-late row is the designed behaviour of a bulk SD replay. |
| `LATE_ARRIVAL_S` | 3 600 s | An absence that resolves within this of the settle horizon is `late_arrival` — a freshness fact, not a loss. Beyond it, absence is loss. |
| `SNAPSHOT_SKEW_S` | 5 s | Maximum permitted difference between the two sides' snapshot instants. Beyond it the two answers are about different moments and the honest verdict is `comparator_fault`, not a row-by-row report of the gap. |

Exclusion is **counted, not silent**: `coverage()` reports `excluded_unsettled`,
`excluded_retention_edge` and `excluded_sampling` separately from `compared`, and an
`accounted` flag that fails when rows vanished between the two. A comparator that folds its
exclusions into its denominator reports 100 % coverage of a window it mostly skipped.

Unanchored time is compared as a **tier**, value ignored, exactly as on the write side. Two
honest readers with no GPS fix will disagree on a wall-clock instant and agree on its
meaning.

## 5. Order, pagination and cursors

These are compared as properties *separate from content*, because two honest readers may
page differently and still answer the same question. A page boundary is not evidence.

**Ordering.** Compared on the declared sort key, over the intersection of the two result
sets, as a count of inversions. Inversions inside `ORDER_GRACE_S` (300 s) are not a finding —
batches legitimately arrive out of order and a gap that closes itself was never a defect.
Ordering is producer-local: a changed `boot_id` makes sequences incomparable, the same rule
`hear_drain.py` already applies to a cursor discontinuity.

**Pagination.** The comparison consumes up to `MAX_PAGES` (20) pages or `MAX_ROWS_COMPARED`
(10 000) rows per query and compares the *concatenation*, never the page boundaries. Page
sizes may legally differ between the two sides. If **one** side truncates at the cap and the
other does not, the two answers cover different extents and the verdict is
`pagination_divergence` with a `reindex_request` — a difference in extent is evidence even
though a difference in page shape is not. Truncation is always recorded in
`sides.*.truncated`; an unrecorded truncation is a coverage claim nobody can check.

**Cursors.** `docs/api-boundaries.md` makes cursors opaque, stable over `created_at,id`, and
expiring after 24 h. Three properties are checked, all before any content comparison,
because unstable paging makes every row-level verdict in the run unfalsifiable:

- **round-trip stability** — re-reading with the same cursor returns the same rows;
- **no duplicates across a page boundary**;
- **no gaps across a page boundary**.

Any of the three fails as `cursor_divergence` (critical, cutover-blocking). A cursor the
comparator itself presented past `CURSOR_TTL_S` is `comparator_fault`, never a divergence:
that is the auditor's scheduling bug, and blaming a store for it is how a comparator loses
its reader. **Cursors are never compared across sides** — an opaque token from one surface
has no meaning on the other, and a comparator that diffed them would be inventing a contract
neither side signed.

## 6. Absence, deletion and retention

The single largest source of false positives in a read comparator is treating "not returned"
as one thing. It is five, and only one of them is loss.

| `row_state` / condition | Verdict | Why |
|---|---|---|
| newer than the settle horizon | `pending` — **no receipt** | in flight; not yet comparable |
| resolved within the late window | `late_arrival` (warn) | a freshness fact; a rising late rate is what *precedes* a loss |
| `retention_expired`, within `RETENTION_EDGE_S` of either declared horizon, or past it | excluded, reported as `match` with the reason recorded | a TTL that fires between two reads is correct behaviour on both sides |
| `retention_expired`, nowhere near either horizon | `retention_divergence` (warn) | one surface pruned something the other still serves, unexplained by policy |
| `tombstoned` on one side, `present` on the other | `tombstone_divergence` (**critical**, blocks cutover) | a deletion that did not propagate is a governance failure a read cutover would make permanent |
| absent past both windows, no tombstone, no retention explanation | `missing_canonical_row` (**critical**, `replay_inbox`, blocks cutover) | the loss this exercise exists to find |
| absent on the legacy side only | `missing_legacy_row` (warn) | not loss — legacy still has everything it ever had — but something is answering from a row the authoritative surface never had |

Retention horizons differ between the two surfaces *by design*: the Phase 3 key design maps
`R1-clip` at 30 d, `R2-raw` at 7 d, `R0-derived` at 90 d, and `R3-evidence`/`R4-audit` not at
all, against a legacy side whose clip rule is a 2 GiB cap rather than an age and whose raw
archives have no retention at all. The comparator therefore compares only inside the
**intersection** of the two declared windows and says so in `coverage`. Comparing outside it
produces a permanently red board out of two healthy stores, which is the same thing as no
board.

Deletion is judged **before** absence for the same reason errors beat absence on the write
side: a tombstone is a recorded fact, and absence is only the absence of evidence.

## 7. Versions and mixed-version behaviour

A staged rollout *is* a mixed-version deployment, so mixed versions are a supported state
rather than an error:

- **Different read-contract majors** between the two surfaces → `version_divergence`, warn,
  not cutover-blocking. Comparison continues over the intersection of fields both majors
  define; additive fields on the newer side are ignored rather than reported.
- **Different projection versions** → `comparator_fault`. The two sides were asked for
  different shapes, and comparing them invents findings. This is the comparator's
  misconfiguration, not a store defect.
- **A receipt from a newer major** is refused with a reason, never guessed (`supported()`).
- **An unknown classification member** from a newer comparator build is preserved verbatim,
  counted as `unclassified` so the accounting still closes, marked `actionable: false`, and
  treated as **cutover-blocking**. A verdict this build cannot interpret is exactly the thing
  a gate must not step over.
- **Per-lane modes, not one global switch.** `HEAR_OBJECTSTORE_MODE_{DRAIN,TAG,SCORE,TDOA,ANNOTATE}`
  are independent, and a fleet with different lanes in different modes is a supported state,
  because that is what a staged rollout is. The comparator records the mode it ran under in
  every receipt.
- Everything within the major is additive: `additionalProperties: true` at every level of the
  receipt schema. A new major is a new file, never an edit to this one.

## 8. Classification

Nineteen members, closed. Every comparison reaches exactly one, or stays `pending`.

| Classification | Severity | Repair | Blocks cutover | Meaning |
|---|---|---|---|---|
| `match` | info | none | no | the two surfaces answered the same way |
| `pending` | info | none | no | inside the settle horizon — **no receipt is written** |
| `late_arrival` | warn | none | no | landed after the horizon, inside the late window |
| `missing_canonical_row` | **critical** | `replay_inbox` | **yes** | the loss this exercise exists to find |
| `missing_legacy_row` | warn | manual | no | a canonical row the authoritative surface never had |
| `duplicate_canonical_row` | **critical** | manual | **yes** | identity-based dedup failed |
| `duplicate_legacy_row` | warn | manual | no | pre-existing redelivery; collapsing it is the designed outcome |
| `count_divergence` | **critical** | manual | **yes** | same settled question, different row count |
| `value_divergence` | **critical** | manual | **yes** | a compared field outside tolerance |
| `order_divergence` | warn | none | no | inversions outlived the order grace window |
| `pagination_divergence` | warn | `reindex_request` | no | one side truncated at the cap, the other did not |
| `cursor_divergence` | **critical** | `reindex_request` | **yes** | paging is not stable or not contiguous |
| `filter_divergence` | **critical** | manual | **yes** | the same request became two questions |
| `retention_divergence` | warn | manual | no | a prune unexplained by either declared horizon |
| `tombstone_divergence` | **critical** | manual | **yes** | a deletion did not propagate |
| `version_divergence` | warn | manual | no | mixed read-contract majors |
| `identity_divergence` | **critical** | manual | **yes** | the surfaces disagree about the producer |
| `comparator_fault` | **critical** | manual | **yes** | the comparator cannot compare, and says so |
| `unclassified` | **critical** | manual | **yes** | no verdict was derivable |

**Order of judgement, and why it differs from the write side.**

```
comparator competence → identity → version → question → cursor → duplication →
deletion → retention → absence → counts → pagination → order → values → digests
```

Competence is judged **first** here, where the write side judges identity first. A read
comparison is a comparison of two *snapshots*: if they are not about the same moment, the
same question and the same projection version, then every row-level verdict beneath that is
a fact about the comparator rather than about the stores. Reporting a skewed snapshot as a
hundred missing rows is the most expensive kind of wrong, because it looks exactly like the
finding the exercise exists to produce.

The rest follows the same logic as the write side: identity beats content because a pair
about two producers is not a pair; duplication beats divergence because with two rows "which
value differs" has no answer; deletion and retention beat absence because a tombstone and a
fired TTL are *recorded facts* while absence is only the absence of evidence.

**Two severity choices worth stating.** `duplicate_legacy_row` is warn because redelivery is
pre-existing legacy behaviour and blaming the new path for the old one's shape trains an
operator to ignore the counter. `comparator_fault` is critical *and* cutover-blocking even
though it is the auditor's own defect, because a gate met by a comparator that was not
looking is not a gate.

**Gate impact is separate from repair action.** "Who fixes this" and "may we proceed" are
different questions, and conflating them is how a blocking finding gets closed as a ticket.
`gate_blocked()` answers the second from a run's tally.

### 8.1 Conservation

```
compared == pending + match + Σ(mismatch classifications)
```

`shadow_read.conservation()` asserts it. If it does not close, the run is not evidence and
must not be reported as one — the same discipline `hear/ingest/batch.py` applies to
`submitted = accepted + duplicate + refused + deferred`.

Coverage has its own conservation:

```
legacy_rows_offered == compared + excluded_unsettled + excluded_retention_edge + excluded_sampling
```

reported as `coverage.accounted`.

## 9. The receipt

`hear.shadowread.receipt.v1` — schema and 26 worked fixtures under
`docs/phase5-shadow-read/`. One receipt per terminal finding, at one of two grains:
`result_set` (a whole answer) or `row` (one row inside it). Both exist because "the count is
wrong" and "this row is wrong" are different findings with different repairs.

| Block | Carries |
|---|---|
| `receipt_id` | `uuid5(namespace, contract ⋮ run_id ⋮ query fingerprint ⋮ row key)` — deterministic, so a re-run after a crash converges instead of duplicating |
| `read_authority`, `read_mode` | pinned `legacy`; the lane mode this ran under |
| `grain`, `window` | result-set or row; window bounds, `as_of` and the settle horizon in force |
| `query` | fingerprint, evidence class, site, devices, bounds, **redacted** filter values, sort, page size, projection version |
| `row` | the row key, when the grain is `row` |
| `sides.legacy` / `sides.canonical` | outcome, row state, row count, page count, truncation, cursor stability, result/state digest, snapshot instant, retention class and horizon, read-contract major, projection version, reader and build, reason codes |
| `verdict` | classification, severity, repair action, **gate impact**, `actionable`, notes |
| `differences` | field path, both redacted values (or nulls for a blind comparison), comparator, tolerance, `quoted`, `blind` |
| `differences_dropped` | how many were elided by the cap — the loss is recorded, never silent |
| `disposition` | `repairable`, `repair_action`, `gate_impact`, `queued` (always `false`), `queue_ref` |
| `sampling` | `sampled`, `rate_denominator`, `forced_reason` |
| `coverage` | offered, compared, the three exclusion counts, eligible, ratio, `accounted` |
| `evidence` | redaction profile and the object keys of the retained answers on each side |
| `comparator` | comparator name, build and receipt major — so a bad comparator release is attributable |

A `pending` comparison **cannot** produce a receipt: building one raises. `pending` is a
scheduling state, not a finding, and writing it down fills the store with rows that mean "ask
again".

The receipt is an index into evidence, never the evidence: ≤ 32 differences, ≤ 8 KiB encoded.
An oversized receipt is refused rather than truncated, because a silently truncated audit
record is worse than a missing one.

### 9.1 Privacy

Redaction is the **write side's**, imported rather than copied:
`READ_VALUE_ALLOW_PATHS` is the union of `reconcile.VALUE_ALLOW_PATHS` and the read-shaped
paths this comparator adds, and the deny pattern is `reconcile.VALUE_DENY_PATTERN` itself.
Two lists drift, and only one of them gets tested on the day it matters.

1. A path matching the deny pattern — `lat`, `lon`, `coord*`, `position`, `token`, `secret`,
   `credential`, `bearer`, `auth*`, `private`, `pem`, `payload`, `body`, `raw`, `audio`,
   `pcm`, `samples`, `clip_bytes` — is redacted. Always.
2. Otherwise, a path on the explicit allow list with a scalar value is quoted literally.
3. Otherwise it is redacted. **An unknown path defaults to hidden**, because a deny list
   defaults to leaked and the next field added upstream is the case that decides which.

Two read-specific additions:

- **Blind comparison.** For a coordinate, a credential or a clip body, equality is decided
  **in memory** and the receipt records only the verdict: both values are `null` and `blind`
  is `true`. Not even a hash — a stable digest of a coordinate is still a stable identifier
  for that coordinate, and a receipt store full of them is a location database with extra
  steps. `tools/coord_guard.py` already makes a real-world coordinate in the tree
  merge-blocking; this keeps the receipt store on the same footing.
- **Filter values are redacted too.** A query is user input, and `?near_latitude=…` is the
  obvious way to reintroduce a coordinate through the one field nobody thought of as data.

Clip audio is never read at all. `clip_manifest` is compared as id, digest, byte length,
sample rate, duration and retention state; the bytes stay where the clip store keeps them and
the receipt carries only an object key.

## 10. Sampled versus exhaustive, and cost

| Rule | Value |
|---|---|
| Mismatch receipts | **always written**, never sampled |
| Exhaustive classes | `ledger_stat`, `model_card`, `export_manifest`, `audit_record` — every run, every row |
| Sampled classes | 1-in-N **queries**, default N = 50, deterministic on the query fingerprint |
| Match (audit) receipts inside a sampled query | 1-in-N **rows**, default N = 1000, deterministic on the row key |
| Forced exhaustive | first 24 h after a lane is enabled; first full day per board class; any window containing a fault-injection drill; any window where a mismatch fired; the final 7 days before a cutover gate |
| Per-query caps | ≤ 20 pages, ≤ 10 000 rows, recorded as `truncated` when hit |
| Receipt caps | ≤ 32 differences, ≤ 8 KiB encoded |
| Cost ceiling | ≤ 1 vCPU-minute per 10 000 compared rows, on existing hardware |

Determinism matters twice: a re-run of a window issues the same query set and audits the same
rows, so coverage is **computable rather than asserted**, and a rolled-back comparator build
can be compared directly against the build that produced a finding.

A misconfigured denominator (0, negative, non-integer) samples **everything**. Failing open
costs storage; failing closed costs the evidence the comparator exists to produce.

If the cost ceiling is breached, the order of response is: raise the query denominator →
raise the row denominator → narrow the window → reduce forced captures. **Never** reduce
mismatch capture, and never sample an exhaustive class.

## 11. Metrics, SLOs and alerts

### 11.1 Metrics

Labels: `site`, `device_id`, `evidence_class`, `class`, `severity`, `side`, `lane_mode`.
Never a token, never a filter value, never a coordinate.

| Metric | Type | Use |
|---|---|---|
| `shadow_read_comparisons_total{evidence_class,grain}` | counter | denominator for every rate below |
| `shadow_read_classified_total{class,severity}` | counter | the conservation equation, live |
| `shadow_read_pending` | gauge | comparisons inside the settle horizon; a rising floor means the canonical path is falling behind, not that it lost anything |
| `shadow_read_excluded_total{reason}` | counter | unsettled / retention-edge / sampling, kept apart so coverage stays honest |
| `shadow_read_coverage_ratio{evidence_class}` | gauge | compared ÷ eligible |
| `shadow_read_coverage_accounted` | gauge | 0 when rows vanished between offered and accounted-for |
| `shadow_read_unclassified_total` | counter | comparator competence; target is exactly zero |
| `shadow_read_faults_total{reason}` | counter | skew, expired cursor, unreachable surface, projection mismatch |
| `shadow_read_lag_seconds{evidence_class}` | histogram | canonical availability minus legacy availability |
| `shadow_read_latency_seconds{side,evidence_class}` | histogram | the read-performance input to the cutover gate |
| `shadow_read_window_closed_timestamp` | gauge | freshness; alert on its **age**, not its value |
| `shadow_read_run_duration_seconds` | histogram | cost-control input |
| `shadow_read_receipts_written_total{class}` | counter | store growth, and the audit trail's own volume |
| `shadow_read_gate_blocking_total{class}` | counter | the cutover gate, live |
| `shadow_read_repair_queue_depth{class}` | gauge | advisory work list; **not** an automation input |

### 11.2 SLOs

| SLO | Target | Source |
|---|---|---|
| Unexplained divergence | **0** over a rolling 14 days | `shadow_read_gate_blocking_total` |
| Comparator faults | **0** per run | `shadow_read_faults_total` |
| Unclassified | **0** per run | `shadow_read_unclassified_total` |
| Coverage | ≥ 99.9 % of eligible legacy rows per window; 100 % for exhaustive classes | `shadow_read_coverage_ratio` |
| Coverage accounting | closes on every run | `shadow_read_coverage_accounted` |
| Freshness | window closed < 30 min ago | age of `shadow_read_window_closed_timestamp` |
| Conservation | closes on every run | run manifest |
| Comparator cost | ≤ 1 vCPU-minute per 10 000 compared rows | `shadow_read_run_duration_seconds` |

"Unexplained" is doing real work. `late_arrival`, `order_divergence`, `duplicate_legacy_row`,
`retention_divergence`, `version_divergence`, `pagination_divergence`, `missing_legacy_row`
and `pending` are **expected** classes with recorded reasons: they are tracked, they are
reviewed, and they do not consume the budget. The nine cutover-blocking classes do.

The canonical read-latency target is **not** set here. `docs/phase4-https-batch-ingest.md`
§16.1 already owes an operator a p99 ingest-lag number, and the read equivalent belongs in the
same decision. The gate below therefore states latency *relative to the measured legacy
baseline* rather than inventing an absolute number this document has no authority to pick.

### 11.3 Alerts

| Alert | Condition | Severity |
|---|---|---|
| Identity divergence | `identity_divergence` > 0 | page |
| Deletion did not propagate | `tombstone_divergence` > 0 | page |
| Canonical read loss | `missing_canonical_row` > 0 sustained 2 runs | page |
| Comparator incompetent | `unclassified` > 0, or `comparator_fault` > 0 on two consecutive runs | page |
| Comparator stalled | `shadow_read_window_closed_timestamp` older than 2 h | page |
| **Implausible zero** | `comparisons_total == 0` while the legacy surface served reads | page |
| Conservation broken | run manifest or coverage accounting does not close | page |
| Unstable paging | `cursor_divergence` > 0 | page |
| Count drift | `count_divergence` > 0 | ticket |
| Divergence drift | `value_divergence` rate rising over 24 h | ticket |
| Late-arrival drift | `late_arrival` rate rising over 7 days | ticket |
| Receipt store growth | receipts/run above the cost ceiling | ticket |

Two rules constrain this list, both inherited deliberately:

- **Alert on implausible zeros, not only on spikes.** A comparator that silently stopped
  produces a perfect dashboard.
- **No alert here may fire on legacy read health.** Legacy is authoritative and unchanged; a
  new page against an unchanged path is a failure mode introduced by the act of observing it.
  A legacy surface that cannot answer surfaces as `comparator_fault`, which routes to the
  comparator's owner, not to the legacy path's on-call.

## 12. Repair queue boundary

The comparator is an auditor. It has **no write path into either subject**, and it never
issues a write of any kind — not to legacy, not to canonical, not to an index, not to a cache.

**Permitted, all advisory:** `none`, `replay_inbox`, `replay_outbox`, `reindex_request`,
`manual_review`. `reindex_request` is a *request recorded for the owner of the canonical read
index*; it is not an instruction this tool may execute.

**Forbidden, and not to be added quietly later:** editing a row on either side; deleting a
duplicate; re-deriving an identity; back-filling a missing row from the other side;
re-issuing a deletion or a tombstone; extending or shortening a retention clock to make two
surfaces agree; auto-enqueueing any of the above.

Every emitted receipt has `disposition.queued = false`, pinned as a `const` in the schema and
asserted by test. The repair queue is an **advisory work list** an operator builds from
receipts; a human dequeues, and the replay that results is an ordinary operation of the
existing store, attributable to that human.

## 13. Operator review and audit trail

One page, and every panel resolves to a receipt query rather than to a number with no
provenance:

1. **Gate status** — the nine cutover-blocking classes, each with its zero line and the
   consecutive-clean-day count. The only panel a promotion decision reads.
2. **Conservation and coverage accounting** — per run. Red if either does not close.
3. **Class breakdown** — stacked by severity over 14 days, expected classes visually
   separated from blocking ones so "expected" never has to be argued in the room.
4. **Freshness, coverage and exclusions** — window-closed age, coverage ratio, and the three
   exclusion counters side by side.
5. **Read latency** — legacy versus canonical p50/p95/p99 per evidence class against the
   recorded baseline.
6. **Top findings** — the newest cutover-blocking receipts with their `receipt_id`, so the
   dashboard is an index into evidence rather than a summary of it.
7. **Repair work list** — queue depth per class, explicitly labelled advisory.

**Evidence bundle**, produced per run and retained for the gate review: the run manifest
(window, `as_of`, settle horizons, counts, conservation result, coverage block, comparator
build, lane modes), the class breakdown, the `receipt_id` list for every cutover-blocking
finding, and the sampling parameters in force. The bundle is **reproducible** — the same
window re-run under the same comparator build produces the same receipt ids — which is what
makes "fourteen days with zero unexplained divergence" a claim somebody else can check.

**Audit trail.** Every operator action against the work list is recorded outside the
comparator, in the existing audit surface, with actor, receipt id, action and reason. The
comparator writes receipts; it does not record who read them, because an auditor that owns
its own audit trail is marking its own homework. Promotion sign-off references the bundle id,
not a screenshot.

## 14. Fault injection

Each case is a fixture in `docs/phase5-shadow-read/fixtures/` and a test in
`tests/test_shadow_read_receipt_v1.py`. The fixture set covers every classification: a
vocabulary member with no worked example is a claim nobody checked.

| # | Injected fault | Expected |
|---|---|---|
| 1 | Nothing; both surfaces answer identically | `match`, forced into the audit sample |
| 2 | Canonical row not yet visible, minutes old | `pending`, no receipt |
| 3 | Canonical row appears 5 min after the settle horizon | `late_arrival`, warn |
| 4 | Canonical row never appears | `missing_canonical_row`, critical, blocks cutover |
| 5 | Canonical returns a row legacy never had | `missing_legacy_row`, warn |
| 6 | Canonical dedup fails; one row returned twice | `duplicate_canonical_row`, judged before any value check |
| 7 | Legacy redelivery returns one row twice | `duplicate_legacy_row`, warn |
| 8 | Same settled question, different row counts | `count_divergence`, critical |
| 9 | One counter in the projection differs | `value_divergence`, critical |
| 10 | A coordinate, a clip body and a credential differ | `value_divergence` with all three differences **blind** |
| 11 | Sort order differs past the order grace window | `order_divergence`, warn |
| 12 | The same inversions inside the grace window | `match` — proves no false positive |
| 13 | One side truncates at the page cap | `pagination_divergence`, `reindex_request` |
| 14 | A cursor does not round-trip to the same rows | `cursor_divergence`, judged before content |
| 15 | Inclusive versus half-open upper bound | `filter_divergence`, critical |
| 16 | A row ages past the legacy 7-day raw horizon | excluded as retention edge — proves no false positive |
| 17 | A row is pruned far from any declared horizon | `retention_divergence`, warn |
| 18 | A tombstoned row is still readable on one side | `tombstone_divergence`, critical |
| 19 | The two surfaces run different read majors | `version_divergence`, warn — a mixed fleet is supported |
| 20 | A credential is forged onto another node's `device_id` | `identity_divergence`, judged before content |
| 21 | The two reads are 45 s apart | `comparator_fault` — the auditor's own defect |
| 22 | The comparator presents a 24 h+ cursor | `comparator_fault` |
| 23 | The legacy surface is unreachable | `comparator_fault` — absence of an answer is not an answer about absence |
| 24 | One surface publishes no digest | `unclassified`, critical |
| 25 | Neither surface has a GPS fix | `match` — tier compared, values ignored |
| 26 | An SD backlog replayed 6 h late on an import lane | `pending` against the backfill horizon |

Cases 2, 7, 12, 16, 19, 25 and 26 exist specifically to prove the comparator does **not**
fire on correct behaviour. A comparator's false-positive rate is what decides whether anyone
reads it, and those seven are the false positives this design would otherwise have.

Drills read from other lanes rather than duplicated here: node outage and reconnect, replayed
batch, cache loss, read-only PVC, the Phase 2 reverse-backfill drill, and the Phase 3 import
verification pass.

## 15. Rollback

Layered, and each layer is cheaper than the one under it. **No reader moves in Phase 5, so
none of these layers is a data operation.**

| Layer | Trigger | Action |
|---|---|---|
| Comparator | cost ceiling breached; `comparator_fault` or `unclassified` > 0 on two consecutive runs; receipt store growth beyond budget | stop scheduling it. Receipts stop; both surfaces are unaffected; no data is deleted; legacy still answers |
| Comparator release | a comparator build changes verdicts with no change on either side | roll the build back and **re-run the window** — deterministic receipt ids make the two runs directly comparable |
| Lane mode | any cutover-blocking class on a lane | return that lane to `shadow`, or to `off`. Per-lane, because a staged rollout that can only be rolled back globally is not staged |
| Design | this lane is abandoned | revert a package, a generator, a document, a decision record, a test and a staged artifact directory that no runtime reads. Regeneration after the revert reproduces the previous bytes exactly, and CI checks it |

There is deliberately **no** "roll back the read cutover" row, because this document does not
perform one. When a cutover is proposed, its rollback is the lane-mode row above plus the
Phase 2 and Phase 3 rollback tables, both of which already exist and both of which keep the
legacy surface live and complete.

## 16. Promotion gates

Two promotions are gated here, and they are not the same thing.

### 16.1 Promoting the receipt contract

`hear.shadowread.receipt.v1` is staged, not published, for the same reason the Phase 4
receipt is: publishing a contract id regenerates `docs/data/phase0-freeze-contracts.v1.json`,
and two lanes regenerating one hashed baseline is a guaranteed conflict in a file where a
conflict is meaningless. The Phase 4 receipt is staged in front of this one and is promoted
first. Promotion is a move plus a regeneration, with **no content change**:

1. `git mv docs/phase5-shadow-read/hear.shadowread.receipt.v1.schema.json contracts/schemas/`
2. `git mv docs/phase5-shadow-read/fixtures contracts/fixtures/hear.shadowread.receipt.v1`
3. Point `OUT_DIR` in `tools/gen_shadow_read_contracts.py` at `contracts/`.
4. Regenerate the freeze baseline (`tools/freeze_contracts.py --format json|markdown`).
5. `python3 tools/check_contract_layout.py`.

### 16.2 Promoting a read lane to canonical (`compare` → `prefer`)

Every clause below is a number a reviewer can check against the evidence bundle, per lane and
per evidence class. **All must hold simultaneously, on the same window.**

| # | Gate | Evidence |
|---|---|---|
| G1 | 14 consecutive days in `compare` with **zero** occurrences of all nine cutover-blocking classes | `shadow_read_gate_blocking_total == 0`, per run, for 14 days |
| G2 | Conservation and coverage accounting close on **every** run in the window | run manifests |
| G3 | Coverage ≥ 99.9 % of eligible rows for sampled classes and **100 %** for the four exhaustive classes, every run | `shadow_read_coverage_ratio` |
| G4 | `count_divergence` = 0 across **every** (device, day) bucket for 14 days | exhaustive aggregate comparison |
| G5 | The final 7 days ran with forced-exhaustive sampling on the lane being promoted | `sampling.forced_reason` on the bundle |
| G6 | Canonical read p99 ≤ 2× the recorded legacy baseline for that evidence class over the last 7 days | `shadow_read_latency_seconds`, baseline captured before the lane was enabled |
| G7 | `late_arrival` p99 ≤ the settle horizon, and its rate flat or falling over the 14 days | `shadow_read_lag_seconds`, `late_arrival` rate |
| G8 | All 26 fault-injection cases green in CI on the comparator build that produced the window | CI run id in the bundle |
| G9 | One full drill inside the window: the lane taken `compare` → `off` → `compare` and the comparator re-run over the same window, reproducing the same receipt ids | drill record + receipt id diff |
| G10 | Every expected-class finding in the window has a recorded reason, reviewed and signed by a named operator | evidence bundle + audit surface |
| G11 | Retention horizons for the lane's evidence classes declared and equal on both sides, or their difference explicitly approved under `docs/data-governance.md` | governance record |
| G12 | Rollback rehearsed to `off` and back within the window, with no legacy reader change | drill record |
| G13 | Operator sign-off recorded against the **bundle id**, not a dashboard screenshot | change record |

A gate met by a comparator that was not looking is not a gate, which is why G2, G3, G5, G8
and G9 are about the comparator's own competence and coverage rather than about the stores.

`prefer` → `only` is **not** gated here. It removes the legacy fallback, which makes it a
different decision with a different rollback, and this document does not have the authority
to pre-approve it.

## 17. Freeze and codegen compatibility

- `hear/verify/shadow_read.py` is the source of truth; every artifact is generated by
  `tools/gen_shadow_read_contracts.py`, wired into the CI job `generated headers are
  current`. A staged artifact with no drift gate stops describing its source just as
  silently as a published one would.
- The contract id constant is named `RECEIPT_CONTRACT_ID`, not `RECEIPT_SCHEMA_ID`, because
  `tools/freeze_contracts.py` harvests `[A-Z_]*SCHEMA[A-Z_]*` assignments as published
  contract ids. A test asserts the constant stays unharvestable, so the reason cannot be lost
  to a rename.
- **This PR moves no baseline hash.** `tools/freeze_contracts.py --check`,
  `tools/check_contract_layout.py`, `tools/recoupling_guard.py` and `tools/coord_guard.py`
  all pass unchanged.
- The module imports `hashlib`, `json`, `uuid`, `typing` and `hear.ingest.reconcile`, and
  performs no I/O at all — asserted by AST, not by grep.
- Nothing in the runtime tree imports it, also asserted by test. A design module reachable
  from a running reader is not a design module.

## 18. Open, and deliberately not decided here

1. **Canonical read-latency target.** Stated relative to the measured legacy baseline (G6)
   rather than as an absolute p99, because the absolute number belongs to the same operator
   decision as the still-open ingest-lag SLO (`phase4-https-batch-ingest.md` §16.1).
2. **Mismatch-receipt retention.** `missing_canonical_row`, `tombstone_divergence` and
   `identity_divergence` receipts are the evidence for a gate review, a deletion incident and
   an authentication incident respectively. Their destruction schedule is a
   `docs/data-governance.md` approval, not a design choice. This design bounds *size* and
   *volume*; it sets no destruction schedule. Carried jointly with the identical open item in
   ADR 0005.
3. **Retention-horizon parity.** Whether the canonical side must match the legacy side's
   effective retention before a read cutover, or whether a documented difference is
   acceptable, is a governance decision (G11 records it as a gate either way). The related
   Phase 2 item O2 — export before partition drop — is still open and is not decided here.
4. **Whether `prefer` requires a separate sign-off from `only`.** This document gates
   `compare` → `prefer` only, and deliberately does not pre-approve the removal of the legacy
   fallback.
